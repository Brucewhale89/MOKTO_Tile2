# 제품 요구사항 문서 (PRD)
## MOKTO 타일 B2B 사이트 — 전체 재구축

## 1. 개요
- **작성일**: 2026-08-10
- **대상**: 홈 / 상세페이지 / 마이페이지·주문내역 / 게시판 Q&A / 관리자 페이지

## 2. 사용자 & 구매 패턴
- **주요 사용자**: 시공업자 (건축 현장에서 타일 구매)
- **구매 패턴**: 기존 거래처 재주문 중심 — 자동/반복 재주문 흐름이 핵심
- **재주문 방식**: 마이페이지 주문내역 → "다시 주문" 버튼
- **주문 단위**: 박스 단위만 (현행 유지)
- **거래처 가격**: 모두 동일가 (거래처별 차등 없음)

## 3. 카탈로그
- 수십 개 핵심 상품 + 소수 주문형(특수) 상품
- 상품 카테고리: 타일(기본) + 거울
- 정렬/그룹: BEST 상품(실 판매량 + 관리자 지정 조합) 상단 고정 → 사이즈별 구분(600×600 등)

## 4. 필터 (우선순위 순)
1. 사이즈 (600×600 등)
2. 재질 (포세린/자기질/도기질)
3. 색상
4. 무광/유광
5. 가격대
6. 도관/솔로몰/외장 사용 용도

## 5. 히어로 섹션
- 목토 시공업 실적 이미지/경향을 전달하는 방향 (실적 기반 신뢰감)

## 6. 상세페이지
- 유지되는 기존 구조 활용 (타일 계산기, 주문 정보, 시공 이미지)
- 정보량이 많아 모바일에서 스크롤이 길어지는 문제 있음 → 탭/아코디언 구조 검토 필요

## 7. 견적서
- **생성 시점**: 장바구니에 담을 때마다 자동 생성 (사용자가 별도 요청 없이)
- 관리자 승인 절차와는 별도 트리거 — 향후 발행 로직에서 구체화

## 8. 알림
- 채널: 카카오톡 / 텔레그램 — 두 채널 동등 우선순위 (사용자가 선택)

## 9. 브랜드 톤
- 미니멀하고 단단함 — 산업/B2B 느낌 (신뢰감, 과장 없는 표현)

## 10. 관리자 페이지 — 우선 기능
1. 재고 실시간 관리
2. 가격 수시 수정
3. 주문 상태 추적 (입금확인 → 배송확인)
4. 시공업자별 거래대장(주문이력)
5. 견적서 자동 발행

## 11. 재사용할 기존 구조
- Home (현재 뼈대) — 유지하며 모바일 대응 리팩터
- 상세페이지 — 유지
- 관리자 페이지 — 유지

## 12. 최우선 문제 — 모바일
**현재 통증**: 정보량이 많아 스크롤이 길어지고, GNB(상단 메뉴)가 좁은 화면에서 깨져 보임.

**해결 방향** (확정):
- GNB → 햄버거 메뉴로 전환 (모바일 폭에서)
- 필터 → 하단 시트(bottom sheet)로 모아넣기

## 12b. 모델명 시리즈 체계 (신규, 확정)
- **목적**: 가격을 간헐적으로 올려도 기존 거래처가 검색/비교로 눈치채지 못하게, 노출용 모델명을 원가/구모델명과 분리
- **패턴**: `ST-시리즈명-색상코드` (예: ST-MOMA-WH)
- **시리즈명**: 단순한 열대/지역감 단어 (모마, 토스카나 등 톤)
- **묶는 기준**: 사이즈별로 시리즈 블록화, 사이즈당 2~3개 시리즈 (재질/광도별로 구분)
- **색상 코드**: 영문 2자 (WH, BK, GR 등)
- **기존 데이터**: BT-xxxx(74종) → 새 이마으로 일괄 자동 매핑/이전
- 실제 원가 모델명(BT-xxxx)은 관리자 화면에만 "더미 모델명" 옆에 노출, 소비자에게는 절대 미표시

## 12c. BEST 커버플로우 (v1.7: 최종 인터랙션 확정, 구현 완료)
- 홈 상단, 기존 BEST5 rank badge 자리를 대체, **범위: BEST 1~7**
- 하단 그리드에서는 BEST 상품 중복 제거 (커버플로우에만 노출)
- 가로 스와이프(터치) + 마우스 드래그, 놓으면 속도 기반 모멘텀으로 미끄러지듯 감속 후 스냅
- 좌우 카드는 스케일만 축소 (불투명도 유지)
- 마우스 오버 시 해당 타일 추가 확대(+10%)
- 하단 글라스(블러) 스크롤바: 더 굵고 길게(8px, 최대 420px), 클릭/드래그로 직접 스크럽 가능
- 카드 디자인은 하단 그리드 카드와 완전 동일(하이라이트·음영·그림자·유광 오버레이·rank-badge 음각), 텍스트도 동일 레이아웃(제품명/사이즈·스펙/판매수·가격)
- "상세보기"만 카드 정중앙(가로+세로)에 투명 배경 + 2px 테두리 글라스 버튼으로 별도 배치, 클릭시에만 상세페이지 이동(드래그로 우연히 이동 안됨)
- 화살표 버튼 원 안 글자 수직 중앙 정렬
- 좌우 화살표 버튼 + 글라스 스크롤바 둘 다 조작 가능

## 12d. 모바일 레이아웃 (확정, 구현 완료)
- 상품 카드: 2열 그리드 유지
- GNB: 햄버거 → 우측 슬라이드 드로어 (Home 적용, 상세페이지 등 전체 확산 예정)
- 필터: 칩(chip) 방식, 하단 시트(bottom sheet)에 그룹별로 세로 나열

## 12f. 필터 UI 세부 (v1.8, 구현 완료)
- 각 필터 행 앞에 얇은 라벨(사이즈/재질/색상/광택) 표시
- "전체" 칩은 라벨처럼 고정 위치에 분리, 나머지 칩들은 별도 wrap 그룹 — 2줄 이상 넘어가도 항상 첫 색상칩(예: 블랙) 위치에서 시작, 전체 밑으로 밀리지 않음

## 12g. 이미지 대비 보정 (v1.8, 구현 완료)
- 화이트/아이보리/베이지/크림/라이트/샌드 계열 색상 타일: brightness(0.8) contrast(1.4) saturate(1.05) 적용해 무늬가 썸네일에서도 잘 보이게 (그리드+커버플로우 공통)
- 그 외 색상: 기존 brightness(0.88) contrast(1.1) 유지

## 12d. 모바일 레이아웃 (확정)
- 상품 카드: 2열 그리드 유지
- GNB: 햄버거 메뉴로 전환
- 필터: **칩(chip) 방식 확정** — 사이즈/재질/색상/무광유광 각 그룹을 라벨 붙은 칩 행으로, 하단 시트 안에 세로 나열

## 12e. 재단 옵션 (확정, v1.9)
- 재단 가능 상품: 600×600만 (다른 사이즈는 해당 없음)
- 결과 사이즈: 600×600 → 600×300 고정 1개 옵션만
- 가격: 원래 박스가 그대로 +20% (박스 수는 동일, 재단이 추가 공정비로 붙는 개념)
- UI 위치: 상세페이지 주문정보 박스 안에 선택 UI(토글/셀렉트)

## 14. 견적서/주문서 자동화 (확정, v1.2)

### 견적서 항목
- 상품명·수량·단가·합계
- 재단 옵션 포함 여부
- 배송지·예금입금자명
- 로고/사업자 정보
- 적용 재질·사이즈·색상

### 견적서 ID
- `거래처번호 + 단순번호` (예: 0032-001)

### 구글드라이브 폴더 구조
- 날짜/일별 폴더 (예: 2026-08/10/)

### 일괄 정리본 (오전 9시 / 오후 4시, 전날 주문건)
- 전체 주문 전적 목록
- 거래처별 모아놓은 리스트
- 배송 주소/배송지 포함
- 계산서·입금 확인된 건만 포함 (미확인 건 제외)

## 15. 열린 질문 (v1.2)
- 상세페이지 정보 구조 개편(탭/아코디언) 방식 확정 필요

- 시공업자별 거래대장의 조회 범위 (전체 vs 최근 N개월)
